# Титаник — предсказание выживших (Random Forest)

Учебный проект: на датасете «Титаник» обучить `RandomForestClassifier`, предсказать `survived`
и сообщить accuracy на тесте. Основной упор — **честность (без утечек данных)** и
**понятный feature engineering**.

**Результат (без утечек):** test accuracy **0.80** на фиксированном split 80/20 (`random_state=42`),
кросс-валидация **~0.82**.

## Особенности / Highlights

- **Аккуратная работа с утечками.** Убрал колонки `boat`/`body` (заполнялись уже после катастрофы —
  дают фейковые ~0.98). Приём «выживаемость по билету» поднимает accuracy на ~2%, но **сознательно
  не использован** — `GroupKFold` по билету доказывает, что это утечка через train/test split (под честным
  разбиением, где семьи не делятся между фолдами, признак не помогает, а вредит). Групповые счётчики
  (`TicketGroupSize`, `FarePerPerson`) считаются по составу группы билета без обращения к таргету —
  утечки ответа нет.
- **Признаки из логики данных.** Титул из имени; «цена на человека» (`fare` делится на размер группы
  по билету); пол×класс; структура семьи/группы. SHAP подтвердил, что «цена на человека» полезнее сырой цены.
- **Проверка гипотез, а не угадывание.** Доп. идеи проверены на точности (кластер, вероятность модели,
  состав группы) — прироста нет, отброшены. Свои «склеенные» признаки тоже проверены ablation'ом:
  `FarePerPerson` помогает, `SexPclass` избыточен для леса (он строит сочетание сам), `NameLength` — шум.
- **Честная валидация.** 5-fold и повторная CV вместо одного сплита (он шумит на ~±1%), плюс
  `GroupKFold` по билету как строгая проверка обобщения на «новых» пассажиров.
- **Интерпретация.** Permutation importance + SHAP — видно, какие признаки и как влияют.
- **Воспроизводимость.** Все random_state зафиксированы, версии библиотек закреплены,
  препроцессинг учится только на train (через `Pipeline`).

## Методология / Methodology

- **Данные:** `fetch_openml("titanic", version=1)` — как в задании, плюс локальный кэш.
- **Признаки:** А (классика: титул, пол, класс, возраст, цена, размер семьи, палуба) +
  Б (цена на человека, пол×класс, приставка билета, флаги ребёнок/мать, число кают).
- **Пропуски:** медиана для чисел, частое значение для категорий (внутри `Pipeline`, только по train).
- **Модели:** сравнение logreg / decision tree / random forest / extra trees / xgboost / lightgbm.
- **Тюнинг:** Optuna (5-fold CV), результат сохраняется в БД (поиск можно прервать и продолжить).

## Ключевые результаты / Key results

| Модель | test accuracy |
|---|---|
| Baseline «всех в 0» | 0.618 |
| RF (по умолчанию) | 0.782 |
| **RF (настроенный) — финал** | **0.802** (CV ~0.82) |

Доп. идеи (кластер, вероятность модели, состав группы) не дали устойчивого прироста — разница в пределах
шума (1 тест-объект ≈ 0.004), поэтому финальная модель оставлена простой. Под строгим `GroupKFold` по билету
честная модель даёт ~0.81 — это самая реалистичная оценка обобщения.

## Почему без GPU

Финальная модель `RandomForestClassifier` (sklearn) работает только на CPU; датасет — 1309 строк,
на таком объёме GPU не ускоряет. Всё считается за секунды на CPU.
